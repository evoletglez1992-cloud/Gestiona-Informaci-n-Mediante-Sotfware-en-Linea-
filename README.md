# Gestiona-Informaci-n-Mediante-Sotfware-en-Linea-
Repositorio para ejercicios y pruebas dela materia de Gestiona Información Mediante Software en Linea  

caracteristicas y desventajas Github:

Caracteristicas:
Control de Versiones con Git: Permite rastrear cambios, volver a versiones anteriores y gestionar el historial de código.
Colaboración y Ramas (Branches): Facilita que múltiples desarrolladores trabajen simultáneamente en el mismo proyecto sin interferir entre sí, permitiendo crear ramas para nuevas funcionalidades.
Pull Requests: Herramienta clave para proponer cambios, revisar código y discutir mejoras antes de integrarlas al proyecto principal.
Repositorios (Públicos/Privados): Aloja proyectos en la nube. Los repositorios públicos son gratuitos y comunes en código abierto, mientras que los privados permiten acceso restringido a equipos.
Documentación y Wikis: Cada repositorio incluye funciones para documentar el código y crear documentación detallada.

Desventajas:
Altos costos para equipos y funciones avanzadas.
Dependencia de la infraestructura de Microsoft.
Preocupaciones sobre la privacidad y el código.
Gestión ineficiente de archivos grandes.
Problemas de disponibilidad y rendimiento.


INVESTIGACION 2 DIFERENCIAS ENTRE:


*REPOSITORY:
Un repository o repositorio es el lugar donde se guarda un proyecto completo en plataformas como GitHub. Se puede comparar con una carpeta inteligente en internet, porque no solo almacena archivos, sino también el historial de todos los cambios realizados en el proyecto. Dentro de un repositorio pueden guardarse códigos, imágenes, documentos y configuraciones necesarias para que un programa funcione. Gracias a esto, los desarrolladores pueden trabajar de forma organizada y segura.

Una de las ventajas más importantes de un repository es que varias personas pueden trabajar al mismo tiempo en el mismo proyecto sin perder información. Además, si ocurre un error, es posible regresar a una versión anterior del trabajo. Los repositorios son muy utilizados en el desarrollo de software, ya que ayudan a mantener ordenados los proyectos y facilitan la colaboración entre equipos. En resumen, un repository es la base principal donde se almacena y administra todo el contenido de un proyecto digital.


*COMMIT
Un commit es una acción que sirve para guardar los cambios realizados en un proyecto. Se puede comparar con el botón de “guardar partida” en un videojuego. Cada vez que un programador termina una modificación importante, realiza un commit para registrar ese avance. El commit guarda exactamente qué cambios se hicieron y quién los realizó, además de incluir un pequeño mensaje explicando la modificación.

Los commits son importantes porque permiten llevar un historial completo del proyecto. Gracias a esto, si ocurre un error o algo deja de funcionar correctamente, se puede regresar a un commit anterior donde todo estaba bien. También ayudan a los equipos de trabajo a entender qué cambios hizo cada integrante. Por ejemplo, un commit puede indicar que se corrigió un error, se agregó una nueva función o se mejoró el diseño de una página. En conclusión, un commit es una forma segura y organizada de registrar avances dentro de un proyecto.


*BRANCH (Rama)
Una branch o rama es una copia del proyecto principal donde se pueden realizar cambios sin afectar el trabajo original. Imaginemos que el proyecto principal es un cuaderno limpio y la branch es una hoja aparte donde alguien puede hacer pruebas o escribir nuevas ideas. Esto permite experimentar de manera segura sin arruinar la versión principal del proyecto.

Las branches son muy útiles cuando varias personas trabajan al mismo tiempo. Cada integrante puede crear su propia rama para desarrollar una función diferente. Por ejemplo, una persona puede trabajar en el diseño de la página mientras otra agrega nuevas herramientas al programa. Cuando los cambios funcionan correctamente, se pueden unir al proyecto principal. Gracias a las branches, el trabajo es más organizado y se reducen los errores. En resumen, una branch es una herramienta que permite desarrollar nuevas ideas de manera independiente y segura dentro de un proyecto.


*PULL REQUEST
Un pull request es una solicitud para unir cambios realizados en una branch al proyecto principal. Funciona como cuando un alumno entrega un trabajo al maestro para que lo revise antes de aceptarlo. En programación, después de hacer cambios en una rama, el desarrollador crea un pull request para que otras personas revisen el código y verifiquen que todo funcione correctamente.
El pull request ayuda a mantener la calidad del proyecto, ya que permite detectar errores antes de agregar los cambios al repositorio principal. Además, facilita la comunicación entre los miembros del equipo, porque pueden dejar comentarios, sugerencias o correcciones. Esta herramienta es muy importante en proyectos grandes donde trabajan muchas personas al mismo tiempo. Gracias al pull request, los cambios se revisan de forma ordenada y segura antes de hacerse oficiales. En conclusión, un pull request es un proceso de revisión y aprobación de cambios dentro de un proyecto colaborativo.

*FORK
Un fork es una copia completa de un repositorio que se guarda en la cuenta personal de otro usuario. Se puede comparar con sacar una fotocopia de un cuaderno para trabajar sobre ella sin modificar el original. Los forks son muy utilizados en proyectos públicos de GitHub, ya que permiten que cualquier persona pueda descargar y modificar un proyecto libremente.
La ventaja principal de un fork es que da libertad para experimentar o mejorar un proyecto sin afectar el trabajo original. Por ejemplo, un programador puede hacer un fork de una aplicación pública para agregar nuevas funciones o corregir errores. Después, si quiere compartir sus mejoras, puede enviar un pull request al proyecto original. Los forks fomentan la colaboración y el aprendizaje entre desarrolladores, especialmente en proyectos de código abierto. En resumen, un fork es una copia independiente de un proyecto que permite trabajar y experimentar de manera libre y segura.
